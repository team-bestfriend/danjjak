# 단계 강조·자막 검증 (#57)

- 요구사항: FR-018~FR-021, UX-011, UX-012
- 관련 시나리오: SC-004, 기존 #61의 단계 행동 기록
- 현재 실행 화면의 저장 단계에서 `targetElementId`와 `instructionText`를 읽는다. 편집 화면이나 홈에서는 단계 안내를 생성하지 않는다.

## 대상 연결

| 저장된 대상 | 화면의 조작 대상 |
| --- | --- |
| source-account-list | 현재 선택한 본인 계좌 버튼 |
| registered-person-list | 패턴에 연결된 인물 버튼 |
| recipient-account-list | 패턴에 연결된 수취 계좌 버튼 |
| amount-keypad | 금액 입력 영역과 내부 숫자·빠른 금액·다음 버튼 (시각적 강조 없음) |
| transfer-summary | 송금 내용을 읽은 뒤 누르는 확인했어요 버튼 |
| pin-keypad | 비밀번호 입력 영역과 내부 숫자·삭제 버튼 (시각적 강조 없음) |

- 키패드는 하나의 복합 입력 영역이다. 내부 숫자 선택은 잘못된 터치가 아니다. 금액·비밀번호 입력 단계는 하이라이트 없이 자막과 음성 안내를 유지한다.
- 강조 스타일은 [원본 프론트엔드](https://github.com/team-bestfriend/frontend/blob/main/src/index.css)의 송금 화면용 `guide-ring`을 그대로 재사용한다. 1.5초마다 노란 빛이 바깥으로 번졌다가 줄어들며, 별도 고정 outline을 덧붙이지 않는다. 원본 복원 요청에 따라 `prefers-reduced-motion`으로 이 효과를 끄는 추가 규칙은 두지 않는다.
- 본인 계좌 변경, 다음, 뒤로가기, 취소, 내용 수정 및 필요한 복구 동작은 허용한다. 다른 수취인·수취 계좌를 누르면 현재 단계에 머물며 잘못된 터치 안내를 보여준다.
- 계좌가 하나라도 저장 패턴에 계좌 선택 단계가 있으면 이를 거친다. 직접 송금의 기존 단일 계좌 분기는 유지한다.
- 대상이 없거나 여러 개면 임의의 요소를 강조하거나 수동 조작을 막지 않는다. 진단에는 고정 오류 코드만 남긴다.
- 조회처럼 대상이 지정되지 않은 단계는 저장 자막만 표시한다. 빈 문구는 금융 결과를 단정하지 않는 일반 안내로 대체한다.

## 자막·오디오·기록

- 전역 안내 하나가 같은 문구를 자막과 TTS에 사용하며, 단계가 바뀌면 이전 재생과 요청을 정리한다.
- 금액·PIN 화면의 중복 음성 안내를 제거했다. 이전 요청의 늦은 실패는 새 안내 상태를 덮지 않는다.
- 안내는 하단 공간을 차지하며 본문 위를 덮지 않는다. 긴 문구는 안내 영역 안에서 스크롤하고, 본문 버튼도 별도로 스크롤해 사용할 수 있다.
- 현재 단계와 방문 식별자가 일치할 때 기존 `recordPatternAction('wrongTouch')`에 연결한다. 기록 동의를 거부했거나 방문이 없으면 기존 저장소가 로그 요청을 보내지 않는다.
- 클릭 좌표, 누른 숫자, PIN, 계좌번호, 자막 원문은 행동 로그나 진단 로그에 추가하지 않는다.

## wrongTouchCount 실서버 확인

1. 이용 기록 동의가 켜진 사용자로 아들 송금 단축번호를 시작한다. 직접 송금이나 시작 전 확인 화면에서는 이 기록을 만들지 않는다.
2. 받는 사람 선택 단계에서 강조되지 않은 딸 카드를 두 번 누른다. 아들 선택 단계에 머물러야 한다.
3. 개발자 도구 Network에서 `PATCH /api/pattern-executions/{executionId}/visits/{visitId}`의 `wrongTouchCount`가 1, 2로 증가하고 요청이 성공하는지 확인한다.
4. 같은 실행·방문의 DB `wrong_touch_count`가 2인지 조회한다. 송금 완료까지 기다릴 필요는 없다. 뒤로 갔다가 다시 들어오면 별도 방문 행이 생성된다.

```sql
SELECT l.pattern_execution_id, l.step_execution_log_id,
       s.step_name, l.visit_number, l.wrong_touch_count, l.started_at
FROM step_execution_logs l
JOIN pattern_steps s ON s.pattern_step_id = l.pattern_step_id
ORDER BY l.step_execution_log_id DESC
LIMIT 20;
```

여러 사용자가 동시에 테스트하면 Network에 표시된 실행·방문 ID와 같은 행을 확인한다. 클릭은 발생했지만 값이 저장되지 않으면 동의 여부, 실행/방문 생성, PATCH 실패 여부를 순서대로 확인한다.
